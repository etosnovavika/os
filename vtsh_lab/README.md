# VTSH — командная оболочка на C (вариант fork, pipe, || + перенаправления ввода-вывода)

Модульная реализация: `repl.c` читает строки, `parser.c` разбивает строку на команды конвейера, `executor.c` запускает команды и конвейеры, `process_manager.c` ожидает процессы через `waitpid()`, `main.c` запускает REPL.

## Сборка и тестирование (Linux / macOS)

```sh
cmake -S . -B build
cmake --build build
python3 -m unittest discover -s test -p 'test_vtsh.py' -v
./build/bin/vtsh
```

**Вариант:** `fork()` создаёт дочерние процессы. **Расширения:** конвейеры `|` и условный оператор `||`, например `/bin/echo hello | /usr/bin/wc -c`.

Для конвейера из N команд создаются N дочерних процессов и N−1 каналов `pipe()`. В дочерних процессах `dup2()` соединяет `stdout` предыдущей команды со `stdin` следующей. Родитель закрывает неиспользуемые концы каналов и ожидает **все** дочерние процессы. Статус конвейера — статус последней команды.

Обычные `cd` и `exit` выполняются в родительском процессе. Внутри конвейера встроенные команды запускаются в дочернем процессе, поэтому `cd` не меняет каталог оболочки, а `exit` не завершает родительскую оболочку.

Парсер поддерживает слова, разделённые пробелами, и оператор `|`, **отделённый пробелами**. Поддерживаются перенаправления **`<`**, **`>`** и **`>>`** (операторы должны быть отделены пробелами):

- `cmd < file` — читать стандартный ввод из файла;
- `cmd > file` — создать/перезаписать файл стандартного вывода;
- `cmd >> file` — дописать стандартный вывод в конец файла;
- `/bin/cat input.txt > output.txt` — перенаправление вывода в файл;
- `/bin/cat < input.txt | /usr/bin/wc -l > count.txt` — перенаправления совместно с конвейером.

Перенаправления применяются после подключения каналов; явное перенаправление имеет приоритет над каналом. Ошибки открытия файла не завершают оболочку. Для встроенных `cd` и `exit` дескрипторы восстанавливаются после выполнения в родительском процессе. Оператор `||` запускает правую часть только при ненулевом статусе левой; цепочки вычисляются слева направо с коротким замыканием. Кавычки, экранирование и `&`, `;`, `&&` не поддерживаются. Для запуска внешних программ используется `execvp()`, без `system()` и `popen()`.

Коды ошибок запуска: 127 для отсутствующей программы, 126 для невозможности выполнить файл. Ошибка синтаксиса — 2. `waitpid()` обрабатывает `EINTR`, статус процесса — через `WIFEXITED`/`WEXITSTATUS` или `128 + сигнал`.

Примеры `||`: `/usr/bin/false || /bin/echo fallback`; `/usr/bin/true || /bin/echo skipped`; `/bin/echo hi | /usr/bin/false || /bin/echo recovered`. Статус конвейера определяется последним звеном.

## Примеры

```text
vtsh> /bin/echo hello | /usr/bin/wc -c
6
vtsh> /bin/echo hello | /bin/cat | /usr/bin/wc -l
1
vtsh> cd /tmp
vtsh> /bin/pwd
/tmp
vtsh> exit
```

При переносе с macOS на Linux нужно удалить `build` и пересобрать проект.

## Дополнительные проверки

В тестах проверяются `cd` и `exit` внутри конвейера (без изменения состояния родительского shell), отсутствующая команда в первом и последнем звене, восстановление после ошибки, `<`, `>`, `>>`, взаимодействие перенаправлений с `pipe`, ошибки открытия файлов и неполный синтаксис, `||` (обе ветви, короткое замыкание, цепочки, взаимодействие с `|` и перенаправлениями).

Операторы отделяются пробелами: `/bin/echo hello > file.txt`, а не `/bin/echo hello>file.txt`. Подстановка переменных, кавычки, перенаправление `stderr` (`2>`) и heredoc не реализованы.
